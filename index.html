Conceptos Clave: Gestión y Organización de Librerías (Guadián, 2025)
Organización
Taxonomía Multidimensional

Consiste en estructurar los prompts siguiendo rutas jerárquicas lógicas (ej: área/objetivo/vertical) combinadas con etiquetas cruzadas. Esto acelera las búsquedas y evita la existencia de duplicados en la base de datos.

Automatización
El Doble Formato

Uso coordinado de Markdown con cabecera YAML Frontmatter (legible por humanos al editar) y JSON (legible por máquinas, orquestadores y APIs de software). Permite separar de forma clara los metadatos del prompt final.

Calidad
Gobernanza y Roles

Define quién puede crear, editar o aprobar prompts. Los roles principales son: Curador (aprueba pases a producción), Editor (diseña borradores) y Lector (operadores que consumen las plantillas validadas).

Conceptos Clave: Plantillas y Placeholders
Estructura
Plantillas de Prompts

Son instrucciones de IA semiestructuradas que aíslan la lógica operativa de los datos reales, permitiendo que la misma instrucción se aplique repetidamente a distintas entradas.

Sintaxis
Placeholders o Marcadores

Etiquetas temporales encerradas entre llaves {VARIABLE} que se inyectan en el prompt. Al ser compilados, se reemplazan dinámicamente por los valores ingresados por el usuario final.

Riesgo
Falta de Normalización

Ocurre cuando las variables no se documentan. Si el operador no sabe qué formato o tipo de valor espera cada placeholder (ej. un texto largo vs un código de ID), la salida del modelo de lenguaje fallará.

Conceptos Clave: Doble Formato e Integración
Sintaxis
YAML Frontmatter

Bloque de texto delimitado por --- al inicio de un archivo Markdown. Su estructura clave-valor permite definir metadatos complejos de forma limpia e intuitiva para los seres humanos.

Consumo
JSON Automatizado

Formato ligero de intercambio de datos. Convierte la estructura YAML y el texto del prompt en claves anidadas que los programas de software o flujos de API consumen de manera robusta.

Beneficio
Independencia de Código

Permite que un diseñador de prompts actualice la lógica y las variables en un archivo Markdown sin necesidad de reescribir o recompilar el código de software de la aplicación que los invoca.

Conceptos Clave: Gobernanza, Versionado Semántico y Mitigaciones
Gobernanza
Versionado Semántico (SemVer)

Normas para incrementar números de versión de un prompt: Mayor.Menor.Parche. Correcciones tipográficas incrementan el parche; agregar variables opcionales incrementa la menor; reescrituras de lógica incrementan la mayor.

Mitigación
Inconsistencia entre Modelos

Un prompt optimizado para GPT-4 puede fallar o volverse redundante en Claude o Llama. La mitigación requiere etiquetar la compatibilidad en los metadatos y re-testear la instrucción en cada actualización.

Mitigación
Baja Adopción del Catálogo

Riesgo de que los usuarios vuelvan a prompts locales ad-hoc. Se mitiga implementando flujos sencillos (ej: Notion o este dashboard), formación interactiva y mostrando ejemplos claros de entrada/salida.

Conceptos Clave: Técnicas Avanzadas de Meta-Prompting
Etapa 1
Auto-meta Prompting

Instrucción diseñada para que un LLM actúe como un "Ingeniero de Prompts" autónomo. Analiza una tarea compleja y diseña la estructura del prompt de sistema óptimo (rol, reglas, formato de salida y variables).

Etapa 2
Orquestación de Expertos

Técnica consistente en estructurar una simulación donde un "Director" descompone un problema y coordina las opiniones de múltiples "Expertos Virtuales" de nicho antes de consolidar la respuesta.

Etapa 3
Refinamiento Iterativo

Bucle de optimización donde el modelo de lenguaje actúa como evaluador de su propio prompt mediante rúbricas objetivas, reescribiendo la instrucción hasta alcanzar una calificación de claridad 10/10.

Guía Avanzada: Versionado Semántico de Prompts (SemVer)

Un prompt no es estático; evoluciona a medida que los modelos de lenguaje cambian, se descubren vulnerabilidades (prompt injection) o cambian las necesidades de negocio. Tratar a los prompts con la disciplina del versionado de software es fundamental para la calidad e integración continua.

Regla de Oro del Versionado de Prompts

Los prompts actúan como contratos de API. Si modificas los nombres de las variables internas que una aplicación inyecta automáticamente, romperás la integración. Es por ello que debes versionar tus prompts siguiendo la regla semántica Mayor.Menor.Parche.

Tipo de Cambio Esquema SemVer Descripción del Cambio Ejemplo Práctico
PARCHE (Patch) x.y.PATCH (ej. 1.0.0 → 1.0.1) Cambios de formato que no alteran la lógica operativa ni las variables de entrada. Corrección de erratas, añadir tildes, clarificar la redacción de un ejemplo interno.
MENOR (Minor) x.MINOR.0 (ej. 1.0.0 → 1.1.0) Adición de nuevas variables (placeholders) opcionales u obligatorias, o ligeros cambios en las instrucciones que modifican el formato de la respuesta. Añadir la variable {TIPO_DE_CAMBIO} a un prompt financiero, o forzar que el formato de salida sea tabla en vez de lista.
MAYOR (Major) MAJOR.0.0 (ej. 1.0.0 → 2.0.0) Cambio radical en la lógica, eliminación de variables que rompe integraciones anteriores, o migración de modelo que requiere reestructurar todo el prompt. Cambiar el modelo de GPT-4 a Claude 3.5 Sonnet reescribiendo la lógica Few-shot a XML tags, o eliminar variables clave como {documento}.
Preguntas Frecuentes (FAQ) del Taller

Respuestas a las dudas más comunes sobre ingeniería de prompts avanzados, repositorios y plantillas.

¿Por qué usamos un doble formato (Markdown YAML + JSON)?
El doble formato resuelve el problema de tener distintos tipos de usuarios en un equipo de IA. Los curadores y editores humanos necesitan redactar prompts en archivos legibles y fáciles de auditar (Markdown con YAML Frontmatter es ideal porque es texto plano formateado). En cambio, los sistemas de software e integraciones de API necesitan leer metadatos de forma estructurada para inyectar variables (el formato JSON es el estándar de comunicación en desarrollo web). Compilar automáticamente de MD a JSON es el puente perfecto.
¿Qué diferencia hay entre un Prompt de Sistema y un Prompt de Usuario?
El Prompt de Sistema (System Prompt) define la personalidad, las reglas de negocio, las limitaciones operativas, el tono y la estructura general del modelo (es la directiva superior). El Prompt de Usuario (User Prompt) le entrega al modelo los datos específicos de entrada para procesar (las variables como {texto_cliente} o {NDA}). En bibliotecas de prompts, la plantilla semilla suele representar el System Prompt o una instrucción unificada.
¿Qué es y cuándo se requiere la recuperación de contexto (RAG)?
RAG (Retrieval-Augmented Generation) consiste en buscar información relevante en bases de datos externas de la empresa e inyectar ese contenido en el prompt del LLM en tiempo de ejecución. Se requiere (RAG = true) cuando el prompt debe analizar un documento que el modelo no conoce de antemano (como contratos específicos de clientes, manuales internos de productos actualizados ayer o balances contables del trimestre en curso).
¿Cómo afecta la temperatura a la consistencia de una plantilla?
La Temperatura controla la aleatoriedad de las respuestas de un modelo de lenguaje. Para prompts de bibliotecas organizadas que buscan reportes, análisis sintácticos o conversión de formatos consistentes, la temperatura debe configurarse baja (ej. 0.0 a 0.2). Para prompts creativos (hilos de redes sociales, brainstorming), se permite una temperatura mayor (ej. 0.7 o 0.8).
¿Qué es y para qué sirve el Meta-Prompting en etapas?
El Meta-Prompting es la técnica de utilizar la inteligencia del propio LLM para que actúe como un diseñador de prompts. En vez de escribir prompts complejos por prueba y error, usamos un Auto-meta Prompt para estructurar una plantilla optimizada. La Orquestación delega tareas específicas a roles expertos para mitigar alucinaciones, y el Refinamiento Iterativo somete el borrador del prompt a una rúbrica autónoma para pulirlo continuamente.
¿Cómo funciona la persistencia en base de datos SQLite y qué pasa si no inicio el servidor?
El sitio cuenta con una arquitectura híbrida de persistencia. Al cargar la página, el frontend intenta conectarse a la API local de Python (/api/prompts). Si el servidor está corriendo (python server.py), las operaciones de lectura, guardado y eliminación se realizan de manera persistente en la base de datos relacional SQLite (prompts.db). Si el servidor está apagado o inaccesible, el sitio conmuta automáticamente a Modo Local (localStorage) del navegador. Esto garantiza que la aplicación siga funcionando y permita añadir, compilar y evolucionar prompts localmente sin interrumpir la clase.
¿Cómo funciona la evolución automática bajo las reglas de SemVer en la interfaz?
Cuando modificas un prompt en cualquiera de las herramientas (Playground, Meta-Prompting, Conversor) y presionas "Evolucionar Prompt", el sistema realiza el cálculo matemático de SemVer de forma automatizada:
  • Parche (Patch): Incrementa el tercer dígito (ej: 1.0.0 → 1.0.1) para correcciones ortográficas o gramaticales sin cambio de variables.
  • Menor (Minor): Incrementa el segundo dígito y resetea el parche (ej: 1.0.1 → 1.1.0) cuando el sistema detecta de forma autónoma que has agregado nuevas variables opcionales o placeholders al prompt.
  • Mayor (Major): Incrementa el primer dígito y resetea los demás (ej: 1.1.0 → 2.0.0) para rediseños estructurales completos o cambios de modelos incompatibles.
Esto previene errores de digitación y asegura la coherencia. Cabe destacar que el repositorio conserva todas las versiones anteriores de forma íntegra en la base de datos (SQLite / LocalStorage) en lugar de sobrescribirlas. Esto crea un historial de versiones completo que permite utilizar o modificar varias versiones del mismo prompt de manera simultánea en producción, según lo requieran diferentes aplicaciones o flujos operativos.
¿Cómo puedo buscar y filtrar prompts por etiquetas?
La biblioteca semilla y los nuevos prompts que registres incluyen un metadato de tipo lista llamado tags. Para facilitar su búsqueda, implementamos una barra de búsqueda en tiempo real que escanea el texto del prompt, su nombre, descripción, taxonomía y variables. Adicionalmente, el sistema extrae automáticamente todas las etiquetas de los prompts registrados en el repositorio y dibuja botones interactivos. Al hacer clic en un tag, el catálogo reduce la vista para mostrar únicamente los prompts asociados a dicha etiqueta, permitiendo combinar filtros fácilmente.
¿Cómo edito un prompt existente y qué significan sus "Estados de Gobernanza"?
Para realizar correcciones tipográficas o modificar detalles de un prompt sin incrementar su versión, puedes usar el botón "Editar" en la ficha del prompt. Al abrir el formulario de edición, podrás cambiar todos sus campos incluyendo la plantilla e instrucción. Adicionalmente, puedes asignarle un Estado de Gobernanza:
  • En Producción (Verde): El prompt está completamente validado y listo para ser consumido de forma general por las aplicaciones u operadores.
  • En Revisión (Amarillo): Se están evaluando cambios o rendimiento en esta plantilla antes de aprobarla.
  • Borrador (Gris): Una plantilla en fase inicial de diseño que no debe emplearse en flujos productivos.
  • Deprecado (Rojo): El prompt es obsoleto o ha sido reemplazado por versiones más estables. Se mantiene por trazabilidad pero no se aconseja su uso.
Puedes filtrar rápidamente los prompts en tu catálogo seleccionando el estado deseado en el selector de filtros al lado del buscador.
¿Cómo funciona el Evaluador de Prompts por IA y cómo resuelvo bloqueos de CORS con Ollama?
El Evaluador IA envía el prompt del usuario y un System Prompt Experto de Ingeniería de Prompts a los servicios de Google Gemini, OpenAI o Ollama. La IA audita la claridad, variables y estructura del prompt (aplicando principios como XML, normalización de placeholders y Chain of Thought), y devuelve un diagnóstico crítico y una propuesta de plantilla optimizada dentro de etiquetas XML <improved_prompt> para extracción automática.

CORS con Ollama local: Los navegadores modernos bloquean por seguridad (política de mismo origen) las peticiones directas desde páginas locales a servicios que corren en localhost. Para solucionar esto en Ollama, debes iniciar el servidor permitiendo orígenes externos. En la consola de Windows ejecuta:
cmd /c "set OLLAMA_ORIGINS=* && ollama serve"
Una vez reiniciado Ollama con esa variable de entorno, presiona el botón 🔄 Cargar en el panel para consultar dinámicamente todos los modelos instalados en tu máquina local.
